# Implementation decisions

A running log of small implementation choices (working rule 10). Architecture or scope changes are agreed first.

| # | Date | Decision | Why |
|---|---|---|---|
| D-001 | 2026-11-07 | Pin Python to 3.11 (`.python-version`, `requires-python >=3.11,<3.12`). | The brief specifies 3.11. The machine default is 3.14, which some ML wheels may not support yet. |
| D-002 | 2026-11-07 | Pin HAPI to `hapiproject/hapi:v8.12.0-2` (latest stable tag on 2026-11-07) with `postgres:16-alpine`. | Reproducible builds. The tag can be changed with `HAPI_IMAGE_TAG`. |
| D-003 | 2026-11-07 | Set HAPI `client_id_strategy: ANY`. | Lets the loader use stable client-assigned ids (`demo-001`, `p-000123`) so personas have fixed URLs. |
| D-004 | 2026-11-07 | HAPI port is bound to `127.0.0.1` locally and not published in deployment. | The brief requires HAPI to stay on the internal network only. |
| D-005 | 2026-11-07 | The `api` and `web` compose services sit behind the `app` profile until M6/M7. | `make up` stays fast and only needs the FHIR store in early milestones. |
| D-006 | 2026-11-07 | Represent CareGap/Flag in FHIR as `DetectedIssue`; the rule id@version and priority components go in extensions. | `DetectedIssue` already has patient, code, evidence and mitigation (the reviewer decision); `Basic` would need more custom structure. To be confirmed in M2. |
| D-007 | 2026-11-07 | pytest skips the `slow` and `integration` markers by default; `make test-all` runs them. | Keeps `make test` and CI fast. HAPI-dependent tests run locally. |
| D-008 | 2026-11-07 | pnpm comes from corepack (`corepack enable`) rather than a global install. | pnpm is not installed on the dev machine; corepack ships with Node. |
| D-009 | 2026-11-07 | Messages are keyed by (pathway, audience, channel, language). Templates are stored one file per language (`content/messages/templates/<lang>.yaml`), plus `matrix.yaml` (what must exist), `slots.yaml` (nominal slot lengths for length checks), `labels/` and `blocklist/`. | Translation can be reviewed per language. The validator checks completeness, declared slots, SMS segments, decline options and blocklists in one place. |
| D-010 | 2026-11-07 | SMS limits are 320 characters for Latin scripts and 140 for Arabic/Indic scripts (2 segments). Each slot is counted at a nominal maximum length. | Follows brief §5.2. Nominal slot lengths make the check independent of real names. |
| D-011 | 2026-11-07 | Bengali (`bn`) speakers receive English messages. There is no `bn` template set. | The brief lists six languages. The gap is kept visible as a language mismatch in the equity console, not hidden. |
| D-012 | 2026-11-07 | The rule DSL has five kinds: `periodic`, `schedule`, `immunisation`, `followup` and `cascade`. The evaluator is a pure function. A `SnapshotView` raises an error if a rule reads any field not in its `data_required`, and records `fields_read`. | Privacy by construction (working rule 8) and traceability. |
| D-013 | 2026-11-07 | `ADULT_T2D_SCREEN` uses a 12-month interval when the last HbA1c is 5.7–6.4% (ADA 2026, Table 2.5). | Without this, demo persona `demo-010` (HbA1c 6.1% 18 months ago) would not be overdue for screening, contrary to brief §11. |
| D-014 | 2026-11-07 | `CASCADE_FH` uses `child_min_age_years: 0` (NICE CG71 1.1.15) and walks first-degree relatives only. | The brief asks for first-degree relatives. NICE also covers second- and third-degree relatives; this is documented as a limitation. |
| D-015 | 2026-11-07 | Publisher pages that block bots (NICE, ADA, AAP) are verified through `verification_url` (Internet Archive, PubMed Central, PubMed). `verify_sources.py` reports 403 as BLOCKED, not FAIL. | Working rule 5 requires each source URL to be fetched; we record how it was verified. |
| D-016 | 2026-11-07 | Standard codes are used only where verified on tx.fhir.org on 2026-11-07. Combination vaccines, BI-RADS, M-CHAT, developmental screen, CIN2+ and advanced colorectal neoplasia use local codes. `docs/CODES.md` is generated from `codes.yaml`. | Working rule 4. |
| D-017 | 2026-11-07 | Commemoration Day (30 Nov) is listed as an observance, not a holiday. It is absent from the 2026 u.ae public-holiday list. | Verified source; avoids closing clinics on a working day. |
| D-018 | 2026-11-07 | OSM clinic points are stored without names and used only for coordinates and density. Generic clinics are placed near clusters of OSM points with a 300–700 m offset. | Working rule 7: no real facility brands. |
| D-019 | 2026-11-07 | Each generator stage (population, latent, consent, history) gets its own RNG from `SeedSequence(seed).spawn`. | Same seed gives byte-identical output, and changing one stage does not reshuffle the others. Tested in `tests/test_generator.py`. |
| D-020 | 2026-11-07 | Pre-history "legacy" screening results are generated 1–6 years before the history window. | Screening intervals of 36–60 months are longer than the 24-month history. Without older results, almost every adult would look never-screened. |
| D-021 | 2026-11-07 | Missed appointments are FHIR `Appointment` (status `noshow`). Attended visits are `Encounter` (status `finished`). Blood pressure is one LOINC 85354-9 panel with systolic and diastolic components. The clinic for a no-show is held in an extension, because R4 does not allow Appointment.participant.actor to be an Organization. | Valid R4 modelling; HAPI rejected the Organization participant. |
| D-022 | 2026-11-07 | Clinic and van IDs use hyphens (`clinic-khalifa-city-1`). | FHIR ids may not contain underscores. |
| D-023 | 2026-11-07 | Latent ground truth lives only in `data/hidden/latent_truth.parquet`. `repo.load_latent()` refuses callers outside `wiqaya.generator`, `wiqaya.simulate` and `wiqaya.evaluate`. | Brief §3.1: models and the API never see it. |
| D-024 | 2026-11-07 | People whose `clinical_data` consent is `not_asked` are excluded, as well as those with `denied`. Both counts are reported. | Privacy by default. The brief names `denied`; `not_asked` (~1%) is treated the same way. |
| D-025 | 2026-11-07 | A genomic finding counts as a cascade index reason only if the index person granted `genomic` consent. A confirmed FH diagnosis counts without it. | Privacy by construction. |
| D-026 | 2026-11-07 | Model R: the reference date is T0−12 months. Features use data before it; the label is a condition detected in the following 12 months, among adults who had a screening visit in that window (observed outcomes only). Model N: one row per past invitation; the label is "no attended visit within 30 days". The data split is by person: 60% train, 20% isotonic calibration, 20% held-out test. | Temporal separation, and brief §6.3 ("observed outcomes only", isotonic calibration). |
| D-027 | 2026-11-07 | The risk component of the priority score is the percentile rank of calibrated risk among scored adults. Children (no Model R score) get a neutral 0.5. Relatives with a cascade gap get a guideline prior (percentile ≥ 0.99, `cascade_risk_percentile`). | A first-degree relative of an FH index has about a 50% carrier probability. The rule, not the population model, should drive their urgency. |
| D-028 | 2026-11-07 | Capacity fit runs in two stages. (1) CP-SAT chooses a site per flag, against 12-week site capacity per slot type, with a household same-site bonus. It is solved per connected group of sites, with one worker and a deterministic time budget. (2) A deterministic fill places each site's flags into weeks by rank, keeping households together. (3) A post-pass moves or swaps household members into a shared week. | The single model with (flag, site, week) variables had 180k variables and did not reach a good solution in time; this version has 15k variables, is reproducible and finishes in about 85 s. |
| D-029 | 2026-11-07 | The fairness floor uses "people with at least one gap of time sensitivity ≥ 0.7" as the need share, and the top-K flags (K = total slots) as the slot share. Promoted flags swap with the lowest-ranked flags of segments still above their own floor. Every swap is logged in the `fairness_log` table. | Brief §6.3. |
| D-030 | 2026-11-07 | The simulator uses common random numbers: SHA-256 of (seed, person or bundle, draw index) gives the same uniform draw under both policies. The baseline targets age/sex-rule pathways only (WCV, immunisation, developmental, adult screening) with one generic SMS. Wiqaya gets the same capacity and the same invitation budget per slot. | A fair comparison (brief §6.6). The baseline gets no follow-up or cascade lists, because today's practice does not have them. |
| D-031 | 2026-11-07 | The uplift T-learner (stretch goal) is **cut** for time: it is first in the brief's cut order. The history period still includes randomised-channel invitations (5% of adults), so it can be added later. Channel escalation (CHW after 2 non-responses) is rule-based. | Cut order in brief §12. |
| D-032 | 2026-11-07 | The optional LLM path (`LLM_ENABLED`) has no bundled provider. `validate_llm_output` (no new numbers, blocklist, length) is implemented and tested, and the deterministic template is always the fallback. | Working rule 9: no model is sent health data in the default build. |
| D-033 | 2026-11-07 | Added a fifth guest role, `clinician`, alongside coordinator, planner, family and admin. Switching role keeps the same session overlay. | Brief rule 8 and §6.2 require clinician-only genomic detail and clinician sign-off of cascade tasks. The brief's role list has no clinician. |
| D-034 | 2026-11-07 | Sessions are `itsdangerous`-signed cookies (or a Bearer token) with a 2-hour TTL. Decisions and preferences are written to an in-memory per-session overlay, never to base data. Guest creation is rate-limited (30/min per IP). | Brief §13 hardening. |
| D-035 | 2026-11-07 | Audit: every person-level read and every write appends an event (role, session prefix, action, entity, fields_read) to memory and `data/audit/audit.jsonl`. | Brief §8.1. |
| D-036 | 2026-11-07 | Cascade outreach previews stay `blocked_until_clinician_approval_and_index_consent` until a clinician accepts the flag in that session. The family view only shows cascade messages after sign-off. | Brief §5.1: CASCADE_FH never auto-contacts. |
| D-037 | 2026-11-07 | Person detail reads `Patient/{id}` from HAPI first (1.5 s timeout). If the person is not in the FHIR sample, or HAPI is down, it uses DuckDB and returns a banner message. | Brief §3.3. |
| D-038 | 2026-11-07 | The web app uses Next.js 14 App Router with client-side pages and a same-origin proxy (`next.config.mjs` rewrites `/api/v1/*` to the API). The session cookie is therefore first-party, and CORS is only needed for direct API use. | Simple, works through Caddy in deployment, no token handling in the browser. |
| D-039 | 2026-11-07 | Typed client: `make openapi` writes FastAPI's schema to `web/openapi.json`, and `openapi-typescript` generates `web/src/lib/api-types.ts`. Pages use a thin `api()` helper because the responses are generic envelopes. | Brief §8.1 asks for a generated client; response bodies are not strongly typed in the prototype. |
| D-040 | 2026-11-07 | Added a "district × nationality" equity segment and a population filter on the district map (all, labour accommodation, under-6s, 65+). These create small cells, so n<11 suppression is visible in the demo. | Every coarse segment in a 20k cohort has n ≥ 11, so hatching would never appear. |
| D-041 | 2026-11-07 | The family graph panel draws only parent, child, sibling and spouse edges. Second- and third-degree relatives are reached through them. Days overdue above 730 display as "> 2 years". | Readability. Never-screened adults otherwise show counts such as "8434 days". |
| D-042 | 2026-11-07 | The optional Synthea path is **cut** (item 3 in the brief's cut order). `make synthea` prints a notice. Ground-truth evaluation works only with the native generator anyway. | Time budget. |
| D-043 | 2026-11-07 | Deployment: the API image generates the seeded cohort and runs the whole pipeline at build time. A one-off `loader` service pushes the FHIR sample into HAPI. Caddy is the only public entry point. HAPI and Postgres stay internal (`docker-compose.deploy.yml`). | Brief §13. Every visitor sees the same run id. |
| D-044 | 2026-11-07 | Without `SESSION_SECRET`, the API now keeps a generated secret in `data/.session_secret` (gitignored), so guest sessions survive local restarts. On a 401 the web client sends the user back to the guest screen; on a network failure or a 20 s timeout it shows a clear error. | A restart left the family page stuck on "Loading your messages…". Deployments still set `SESSION_SECRET` in `.env`. |
| D-045 | 2026-11-07 | **Scope change approved by the team:** an optional AI *planner analyst* (Claude Haiku 5.5 by default for cost, set by `AGENT_MODEL`; Anthropic SDK tool-use loop). This goes beyond working rule 9, which limits the LLM to slot-filling and paraphrase. Fences: only the planner and admin roles; tools reach only suppressed aggregate endpoints (no person-level tool, so pseudonymised-or-better by construction); every answer number is checked against tool results; the agent drafts at most 3 proposals per question and a planner must approve or dismiss each; questions, answers and decisions are audited; at most 8 steps, 15 questions per hour per session; off unless `ANTHROPIC_API_KEY` is set. Capacity what-ifs are a labelled rough estimate from simulated rates, not a re-simulation (a full re-run takes ~90 s). | The team asked for agentic AI capabilities and chose the planner analyst with pseudonymised data. Aggregate-only tools keep the privacy rules intact. |
| D-046 | 2026-11-07 | The planner analyst was checked end to end against the live Claude API (`claude-haiku-5-5`). One question (unmet need vs capacity, best van day) took 23 s: 5 aggregate tool calls, 2 proposals awaiting approval, 9 of 12 figures matched by the number check. The 3 unmatched figures were the model's own arithmetic, and the answer labelled them as such. Usage: about 2.3k output tokens and 11k cached input tokens. | Confirms that the fake-client tests reflect real model behaviour, and that the cost is acceptable for a public demo. |
| D-047 | 2026-11-07 | Hackathon public URL: the **web app on Vercel** (root `web/`, `API_ORIGIN` rewrite) and the **API as one container** on Railway, Render or Fly.io (`docker/api.Dockerfile`, which now honours `$PORT` and proxy headers). HAPI is not deployed for the public demo. The VPS + Caddy target and the Azure pilot path stay documented. | The team asked for Vercel. The API is stateful (in-memory sessions, analyst threads, the DuckDB read model), so it cannot run as serverless functions. |
| D-048 | 2026-11-07 | Brand logo and icons were added, then removed at the team's request. The header shows the "Wiqaya وقاية" wordmark as text. Share metadata (title, description, `metadataBase`) is kept. | Team preference. |
